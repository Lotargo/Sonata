# Архивный отчёт: агентский флоу Sonata

> Исследованная версия: 28.1 `Unified Core`  
> Дата анализа: 12.07.2026  
> Статус: исторический донорский материал

## 1. Назначение

Этот документ сохраняет полезные идеи прошлой реализации Sonata, но не определяет технологии новой версии.

Актуальная архитектура mini MVP находится в:

```text
docs/stage-01-core/plan/MINI_MVP_ARCHITECTURE.md
```

## 2. Основной pipeline прошлой версии

```text
user request
-> input classification
-> Archivarius context plan
-> memory retrieval
-> five parallel perspective pipelines
   -> Phase 1 raw response
   -> Phase 2 self-criticism
   -> Phase 3 structured summary
-> Phase 4 Synthesis
-> response post-processing
-> memory write
```

Пять перспектив:

- Logic;
- Imagination;
- Conscience;
- Efficiency;
- Reason.

Каждая перспектива проходила три последовательные фазы. Пять перспектив исполнялись параллельно, после чего Synthesis получал все доступные отчёты.

## 3. Реестр ролей

| Группа | Количество |
|---|---:|
| Phase 1 | 5 |
| Phase 2 | 5 |
| Phase 3 | 5 |
| Synthesis | 1 |
| Utility roles | 2 |

Всего архитектура содержала 18 ролей:

- 15 фазовых ролей;
- `synthesis`;
- `archivarius`;
- `librarian_naming_agent`.

Отдельные старые комментарии ошибочно называли число 17.

## 4. Prompt и manifest

```text
prompts_sonata/
├── logic.json
├── imagination.json
├── conscience.json
├── efficiency.json
├── reason.json
├── synthesis.json
├── archivarius.json
├── critical_thinking/
├── summarizer/
└── manifests/
```

Каждая роль имела:

- системное сообщение;
- task prompt;
- manifest;
- параметры генерации;
- алиас модели;
- формат результата.

Основные placeholder:

```text
{task}
{chat_history}
{archivist_context}
{manifesto}
{report_from_phase1}
{report_from_phase2}
{emotional_state_vector}
{full_reports_text}
```

Manifest задавал основную философию перспективы и набор специализированных способов анализа. Prompt, manifest, память и результаты предыдущих фаз объединялись общим Prompt Assembler.

## 5. Изоляция фаз

### Phase 1

Каждая перспектива получала запрос, историю, память и собственные инструкции. Первичные перспективы не должны были зависеть от текущих ответов друг друга.

### Phase 2

Каждый критик видел только сырой ответ собственной перспективы и проверял ошибки, предпосылки, противоречия и границы применимости.

### Phase 3

Каждый суммаризатор получал Phase 1 и Phase 2 только своей перспективы и создавал структурированное метакогнитивное резюме.

### Phase 4

Synthesis получал все доступные результаты, формировал единое решение Sonata и отделял публичный ответ от служебной части.

## 6. Исполнение ролей

Общий executor:

1. Получал релевантную историю и память.
2. Загружал prompt и manifest роли.
3. Собирал полный контекст.
4. Вызывал назначенную модель.
5. Повторял запрос при временной ошибке.
6. Возвращал текст, модельный алиас и статус.

Новая Sonata сохраняет собственный явный executor и cognitive state machine без универсального агентского фреймворка.

## 7. Модельная маршрутизация

Полезный паттерн прошлой версии:

```text
agent role
-> model alias
-> provider route
-> concrete model
```

Это позволяло:

- менять модель конфигурацией;
- не связывать роль с конкретным провайдером;
- задавать разные параметры генерации;
- продолжать работу при временной недоступности основной модели.

## 8. Память

Прошлая система использовала:

- небольшое окно свежего контекста;
- Qdrant для долговременной памяти и документов;
- dense search;
- поиск по ключевым словам и tags;
- session filters;
- фоновое создание summary и индексацию.

Историческая реализация создавала большое количество отдельных коллекций для ролей и типов данных. Эта схема не переносится в mini MVP.

В новой версии:

```text
Neon -> canonical source of truth
Qdrant Cloud -> rebuildable retrieval projection
```

## 9. Graceful degradation

Полезные свойства:

- timeout для фаз;
- повторные попытки;
- продолжение цикла при падении отдельной перспективы;
- передача Synthesis всех доступных отчётов;
- явные статусы успешного, деградировавшего и неуспешного запуска.

## 10. Что переносится

Переносятся:

1. Пять изолированных призм.
2. Raw, Critical и Summary фазы.
3. Отдельный Synthesis.
4. Archivarius как планировщик контекста.
5. Файловые prompt и manifest.
6. Версионирование инструкций.
7. Модельные алиасы.
8. Graceful degradation.
9. Наблюдаемость каждого agent run.
10. Разделение canonical storage и retrieval index.

Не переносятся автоматически:

- локальная тяжёлая инфраструктура;
- десятки Qdrant collections;
- старый UI;
- старые API endpoint;
- автономия;
- конкретная реализация оркестратора;
- устаревшая структура сервисов.
